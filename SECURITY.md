# Security policy

## Supported version

Security fixes target the current `main` branch. Tagged releases will be listed here after the first verified Release is published.

## Reporting a vulnerability

Do not put credentials, private data, exploit details or identifiable user material in a public Issue.

Use GitHub's private **Report a vulnerability** flow when it is available. If it is unavailable, open a minimal public Issue stating that you need a private security channel, without including sensitive details.

## Skill safety boundary

Agent Skills may inherit the host Agent's ability to read files, execute commands, use browsers or call external tools. Review `SKILL.md`, scripts, dependencies and permissions before installation. Install only Skills you trust and test them with non-sensitive data first.
