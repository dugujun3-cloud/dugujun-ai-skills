# 活动、激励与自动化旅程

用于回答“要不要做活动、券或补贴怎么发、大促如何分阶段、CRM 自动触达为什么没有效果、如何避免过度营销”。本模块把活动视为可验证的行为干预，不提供脱离用户、利润和履约事实的玩法清单。

## 1. 适用问题与边界

适用于：

- 日常活动、节点营销、大促、预售、返场和活动复盘。
- 优惠券、满减、折扣、赠品、积分、补贴等激励机制。
- 新客欢迎、激活、复购、续费、召回等 CRM 自动化旅程。
- 人群圈选、触发条件、渠道组合、频控、冲突与退出规则。
- 活动增量、成本、退款、投诉、作弊和履约风险判断。

不直接替代：

- 产品定价、毛利核算、库存计划、现金流、税务与法务审批。
- 消息系统、优惠引擎、CDP、CRM 或营销自动化平台的工程实施。
- 没有合格反事实时的因果证明。
- 用补贴掩盖产品价值、供给、价格、体验或履约问题。

遇到价格体系、供给能力或履约承诺不成立时，先指出责任边界并转交相关团队，不继续放大活动。

## 2. 最少输入

信息不足时仍可输出诊断框架，但降低结论强度。至少收集：

| 输入 | 最低要求 |
|---|---|
| 决策问题 | 拉新、激活、清库存、转化、复购、续费、召回或其他单一主要目标 |
| 目标用户 | 生命周期阶段、进入/排除规则、当前障碍 |
| 目标行为 | 用户要完成的可观测行为及成熟窗口 |
| 基线 | 同窗历史、自然基线、对照组或其他反事实 |
| 激励 | 类型、面额或价值、门槛、有效期、可叠加规则、预计单位成本 |
| 旅程 | 当前入口、关键步骤、触达渠道、频次、成功与退出事件 |
| 经济性 | 收入或贡献毛利口径、权益成本、渠道和履约成本、退款 |
| 资源约束 | 预算、库存、客服/销售承接、技术、审批和时间 |
| 风险约束 | 退订、投诉、作弊、价格保护、消费者权益、隐私同意 |

没有用户级标识时可做聚合漏斗；没有成本或毛利时不能判断增量利润与 ROI；没有对照或可信基线时只能报告描述性结果。

## 3. 诊断步骤

### 3.1 把活动目标改成决策问题

不要用“做一场大促”“发一批券”作为目标。改写为：

```text
对 [目标人群]，用 [活动/激励机制] 解决 [当前障碍]，
希望在 [观察窗口] 内提升 [主要行为]，
相对于 [反事实] 产生 [业务结果]，同时不突破 [护栏]。
```

目标只能有一个主要决策指标。GMV、参与人数、核销率和消息点击可作为过程指标，不能自动等同于增量价值。

### 3.2 判断问题是否需要激励

先区分障碍：

| 障碍 | 先验证什么 | 激励角色 |
|---|---|---|
| 用户不知道价值 | 信息、演示、试用路径是否清晰 | 激励通常不是首选 |
| 用户缺少行动时机 | 场景触发、提醒和路径摩擦 | 可用轻提醒或低成本激励 |
| 用户有价格阻力 | 支付意愿、竞品、门槛和价格结构 | 小范围验证价格敏感性 |
| 用户缺少信任 | 证据、服务、售后和履约承诺 | 折扣不能替代信任 |
| 产品或供给不匹配 | 核心价值、库存、质量、交付能力 | 停止用补贴掩盖问题 |
| 存在习惯或切换成本 | 首次价值、连续行为和迁移成本 | 激励只作为过渡，不长期依赖 |

若不发激励也会自然完成，激励可能只是成本转移。优先建立未触达人群、随机保留组、地域/时间切换或同窗基线。

### 3.3 检查人群、机制与时机

对每个人群回答：

1. 用户现在处于哪个阶段，刚发生了什么事件？
2. 阻碍目标行为的是价值、价格、信任、路径还是供给？
3. 激励改变了哪个选择，是否可能挤占自然购买？
4. 用户何时需要看到信息，过早或过晚会怎样？
5. 成功后应进入什么状态，失败后是否需要降级或停止？

不得仅按“高价值/低价值”粗分后统一发券。至少加入生命周期、需求场景、历史激励响应和风险排除条件。

### 3.4 检查活动全旅程

```text
符合资格 → 看见活动 → 理解规则 → 领取/报名 → 完成目标行为
→ 履约/核销 → 退款或售后 → 后续留存/复购 → 成熟复盘
```

逐步记录进入人数、完成人数、耗时、失败原因、数据来源和负责人。优先修复损失规模大、接近业务结果、可被干预且可被验证的节点。

### 3.5 检查成本、产能与风险

完整成本至少检查：

- 权益、补贴、赠品和积分负债。
- 媒体、渠道、素材和技术成本。
- 客服、销售、门店、仓储、配送和售后增量成本。
- 退款、取消、拒收、套利与异常订单。
- 对正常价购买、其他渠道和后续购买的挤占。

在上线前确认库存、服务名额、券预算、系统并发、客服响应和退款能力。没有产能上限就不能设计放量计划。

### 3.6 检查自动化旅程

对每条自动化规则做冲突审计：

```text
进入事件 → 资格条件 → 延迟 → 消息/权益 → 渠道 → 频控
→ 成功事件 → 退出事件 → 冲突优先级 → 冷却期 → 负责人
```

重点排查：重复进入、跨旅程叠加、购买后仍被催单、投诉或退订后继续发送、券已使用仍重复提醒、同一用户被多个部门同时触达。

## 4. 判断规则

### 4.1 活动是否可上线

同时满足以下条件才进入小流量验证：

1. 目标人群、目标行为和当前障碍明确。
2. 机制与障碍有可解释联系，而不是“大家都在做”。
3. 主要指标、反事实、成熟窗口和护栏已定义。
4. 完整成本、预算上限和履约产能可获得或可保守估计。
5. 规则、资格、叠加、退款、退出和异常处理可被系统执行。
6. 用户告知、数据使用、消费者权益和审批边界已确认。

任一关键条件缺失时，输出补数或沙盒方案，不直接建议全量上线。

### 4.2 券与补贴怎么选

| 机制 | 适用假设 | 必须验证 | 主要风险 |
|---|---|---|---|
| 无门槛券 | 小额价格摩擦阻止首次行动 | 增量转化和自然购买挤占 | 羊毛党、低质量用户 |
| 满减/阶梯券 | 用户有需求但订单结构未达到目标 | 客单、件单、毛利和拆单 | 过度购买、退货套利 |
| 品类/场景券 | 需求明确但指定场景转化弱 | 场景匹配和替代效应 | 错配、库存压力 |
| 限时激励 | 用户有意向但缺少决策时点 | 真实紧迫性和投诉 | 虚假稀缺、价格信任受损 |
| 赠品/服务权益 | 非价格价值能降低信任或体验障碍 | 使用率、履约成本和价值感知 | 产能不足、兑现失败 |
| 行为积分 | 需要鼓励连续的目标行为 | 行为质量和积分负债 | 刷任务、规则复杂 |

不要自行给出固定面额、折扣、有效期或人群比例。它们应由历史分布、毛利、预算、行为周期、最低可检测变化和履约能力决定。

### 4.3 自动化旅程优先级

当同一用户同时命中多条旅程时，通常按以下原则决策，而非机械群发：

1. 安全、合规、服务故障和履约通知优先于营销。
2. 用户主动请求和正在进行的交易优先于泛促销。
3. 最接近当前生命周期状态的单一旅程优先。
4. 已完成目标、已退订、已投诉、资格失效或风险命中时立即退出。
5. 无法确认冲突优先级时宁可暂缓营销触达。

## 5. 策略与实施

### 5.1 活动决策卡

| 字段 | 内容 |
|---|---|
| 决策 | 放大、调整或停止什么活动/激励 |
| 人群 | 进入、排除、去重和退出规则 |
| 障碍 | 已验证事实、待验证假设 |
| 机制 | 为什么该动作可能改变目标行为 |
| 路径 | 入口、规则理解、行动、履约、售后 |
| 权益 | 类型、门槛、有效期、叠加和成本 |
| 反事实 | 对照、保留组、自然或同窗基线 |
| 指标 | 一个主要指标、诊断指标和护栏 |
| 资源 | 预算、库存、系统、客服/销售、负责人 |
| 停止 | 成本、风险、质量和履约阈值 |

### 5.2 大促分阶段执行

阶段不按固定天数硬编码，按用户决策周期和数据成熟期安排：

| 阶段 | 主要任务 | 必要产物 | 退出条件 |
|---|---|---|---|
| 设计 | 定目标、人群、机制、基线、预算和风险 | 决策卡、规则表、实验卡 | 上线闸门通过 |
| 蓄水 | 识别明确需求和意向，不提前透支触达 | 意向分层、内容与触达序列 | 达到样本或时间条件 |
| 转化 | 按人群和障碍匹配动作，监控成本和产能 | 实时看板、异常清单 | 风险触发或活动结束 |
| 补救 | 处理失败支付、库存、履约、退款和未完成路径 | 补救队列、服务工单 | 用户解决或退出 |
| 留存 | 区分活动购买与真实价值，承接首次价值和复购 | 新客/活动 Cohort | 成熟窗口到达 |
| 复盘 | 估计增量、完整成本、质量和可迁移条件 | 复盘卡、规则更新 | 做出放大/调整/停止决策 |

### 5.3 CRM 自动化旅程表

| 旅程 | 目标人群 | 进入事件 | 条件 | 延迟 | 内容/权益 | 渠道 | 频控 | 成功事件 | 退出/冷却 | 冲突优先级 |
|---|---|---|---|---|---|---|---|---|---|---|

上线顺序：先事件准确性和退出规则，再单条旅程小流量验证，最后才增加渠道和分支。任何自动化都必须保留人工暂停、审计日志和版本回滚能力。

## 6. 指标

### 6.1 主要与诊断指标

- 增量有效新客、激活、首单、复购、续费或召回人数，按决策选一个。
- 各旅程步骤转化率、完成耗时、资格覆盖、领取、使用和履约完成。
- 同窗用户后续留存、复购、贡献毛利或业务指定质量指标。
- 自动化进入、触达、成功、退出、冲突、失败和人工接管率。

### 6.2 经济性

```text
增量人数 = 实验组结果 - 合格反事实结果
单个增量结果成本 = 完整增量成本 ÷ 增量结果数
增量利润 = 增量贡献毛利 - 权益及活动相关完整增量成本
增量 ROI = 增量利润 ÷ 活动相关完整增量成本
```

没有合格反事实时，改称“归因结果”和“描述性 ROI”，不得写成增量。核销率高可能只是券给了本来会购买的人，不能单独证明有效。

### 6.3 护栏指标

- 退款、取消、拒收、投诉、退订和拉黑。
- 异常领取、批量账号、设备/地址聚集和套利。
- 毛利、自然购买挤占、客单结构和后续价格敏感。
- 库存缺货、延迟履约、客服等待和服务兑现失败。
- 触达频次、跨旅程冲突、渠道失败和用户疲劳。

## 7. 护栏

- 规则公开资格、门槛、有效期、数量、叠加、退款和失效条件，不使用误导性稀缺。
- 营销触达须有合法用途和适当同意，提供退订、撤回和人工申诉路径。
- 只使用完成决策所需的最小数据；敏感人群与属性不用于歧视性定价或不当排除。
- 反作弊规则要允许误伤复核，不能以模型评分自动拒绝合法用户的重要权益。
- 不因活动短期结果牺牲售后、服务、安全、品牌和长期用户价值。
- 不引用无来源行业核销率、活动周期、折扣力度或品牌案例作为决策依据。

## 8. 停止条件

出现以下任一情况，暂停新增流量或自动化触达并进入排查：

- 主要事件、资格、成本或对照数据失真，无法判断结果。
- 完整成本、边际成本或补贴消耗突破经批准的业务上限。
- 退款、投诉、退订、作弊、隐私或消费者权益风险突破预设护栏。
- 库存、客服、销售、门店、系统或履约能力不能兑现承诺。
- 同一用户出现冲突旅程、已成功仍触达、已退出仍发送等严重规则错误。
- 描述性提升主要来自自然购买挤占、用户结构变化或观察窗不一致。
- 产品价值或供给问题已成为主瓶颈，继续发券只会扩大损失。

## 9. 输出契约

活动、激励或自动化任务默认输出：

1. 决策结论、适用边界和置信度。
2. 目标人群、当前障碍和目标行为。
3. 活动/激励机制与不采用激励的备选方案。
4. 全旅程卡点与自动化冲突审计。
5. 活动决策卡或 CRM 自动化旅程表。
6. 实验、反事实、指标字典和成熟窗口。
7. 完整成本、履约产能和增量判断边界。
8. 上线、放大、调整和停止条件。
9. 7 天验证动作与 30 天机制建设。
