# 留存、流失预警与召回

## 适用问题与边界

用于处理用户完成首次价值后没有持续回来、留存曲线恶化、高价值用户行为下降、沉默用户召回无效或召回后再次沉睡的问题，例如：

- 次期或长期留存下降，但团队只看到一个整体数字。
- 不知道应该用日、周、月、购买周期还是合同周期定义留存。
- 用户活跃、购买、使用或贡献开始下降，想建立流失预警。
- 所有沉默用户都收到同一张券，成本高且投诉多。
- 召回率看起来提高，但自然回流、补贴用户和重复触达没有被剔除。
- 用户回来一次后再次沉睡，没有恢复核心价值行为。

本模块区分三个任务：

```text
留存 = 在合理机会窗口持续完成价值行为
预警 = 在正式流失前识别可干预的行为变化
召回 = 对已沉默且值得挽回的用户恢复核心价值行为
```

边界：

- “回来打开”不等于留存或召回成功；必须完成约定的价值行为。
- 不同业务、用户和产品有不同使用机会，不使用固定的日/周/月阈值。
- 季节性、长购买周期、合同等待期或暂时没有需求不能直接判定为流失。
- 低留存可能来自产品价值、价格、供给、履约、服务或渠道质量，运营不能用补贴掩盖根因。
- 流失预测模型只能给风险概率，不能证明原因，也不能自动决定高风险处置。
- 明确拒绝、退订、投诉未解决、无触达许可或经济上不值得挽回的用户不进入召回。

## 最少输入

| 输入 | 最低要求 |
|---|---|
| 留存起点 | 激活、首购、首次交付、首次采用等明确事件 |
| 回访行为 | 能代表持续价值的行为，而非仅打开 |
| 机会/观察窗口 | 自然使用、复购、续约或项目周期及依据 |
| Cohort 数据 | 匿名用户 ID、起点时间、回访事件时间 |
| 分群字段 | 渠道、产品、生命周期或价值层之一 |
| 行为历史 | 核心行为频次、间隔、深度或贡献趋势 |
| 当前动作 | 留存机制、触达、权益、服务和召回规则 |
| 经济性 | 可归因成本及毛利/贡献口径，缺失时标记未知 |
| 风险约束 | 触达许可、频控、退订、投诉、履约和服务容量 |

只有汇总留存率时可以做现象描述和补数方案，不能给个体预警名单或因果结论。

## 诊断步骤

### 1. 统一留存口径

定义：合格 Cohort、起点事件、回访事件、观察窗口、去重、迟到数据和成熟条件。交易业务可用再次购买或周期内复购；内容/工具可用核心使用；B2B 可用关键功能采用、活跃席位、里程碑交付或续约状态。

同时保留三种视角：

- 日历留存：固定日、周或月是否返回。
- 区间留存：窗口内是否至少返回一次。
- 机会留存：真实需求或合同机会出现时是否完成目标行为。

选择一种作为主口径，其他只能辅助解释。

### 2. 画 Cohort 留存曲线

按同一成熟窗口比较不同进入时间、渠道、产品或关键人群。检查：

- 早期陡降：首次价值、承接或用户匹配问题。
- 某时点断崖：活动结束、版本、供给、价格、触达或口径变化。
- 长期持续下降无稳定区间：持续价值或使用理由不足。
- 整体稳定但结构变化：高质量 Cohort 被低质量新增掩盖，或反之。

曲线形态只能定位时间，不直接解释原因。

### 3. 比较留存者与流失者的路径

寻找双方在同一机会窗口内的行为差异：完成过哪些功能、内容、服务或交易；在哪一步停下；最后一次成功和失败事件是什么。静态画像只作辅助，优先使用可干预行为。

对关键行为候选检查选择偏差：高意愿用户可能本来就更容易完成该行为。先形成假设，再用引导实验验证。

### 4. 建立原因树

至少保留以下候选分支：

| 原因域 | 证据示例 | 责任边界 |
|---|---|---|
| 没有需求或周期未到 | 未出现使用机会、品类天然低频 | 不提前判流失 |
| 首次价值不足 | 激活后很快离开、未完成关键结果 | 激活/产品 |
| 产品或路径受阻 | 错误、性能、入口、配置、支付失败 | 产品/技术 |
| 供给与履约 | 缺货、内容不足、交付延迟、服务失败 | 供给/服务 |
| 价格与价值不匹配 | 到期或价格变化后流失、异议反馈 | 定价/运营 |
| 用户被替代方案吸引 | 竞品使用或需求转移证据 | 产品/市场 |
| 触达伤害 | 投诉、退订、卸载随频次上升 | 运营 |
| 数据问题 | 埋点、身份、窗口或 Cohort 异常 | 数据 |

用户访谈、VOC 和客服记录用于验证原因，不用单个意见代表整体。

### 5. 定义流失与预警信号

先从本业务行为间隔分布、合同节点或需求周期确定“异常”，再定义：

- 正常波动：仍处于合理机会窗口。
- 风险上升：核心行为频次、深度、成功率或贡献持续偏离个人/同层基线。
- 沉默：已经错过一个或多个合理机会，但尚未满足正式流失规则。
- 流失：超过业务定义窗口且核心关系已中断。

预警信号应满足：在流失之前出现、可以稳定测量、与流失有时间顺序、可被行动影响、错误触达成本可接受。

### 6. 评估可挽回性和优先级

不用“高风险就是高优先级”。按以下维度排序：

```text
优先级 = 历史/未来价值 × 可挽回证据 × 触达许可 × 机制匹配
           ÷ 成本、履约压力与用户风险
```

该式只表达决策方向，不在缺少数据时生成权重。高价值但不可挽回、低价值且成本高、明确拒绝或投诉未解决的用户降低优先级或排除。

### 7. 设计留存或召回实验

预防流失优先于事后召回。一次验证一个机制：修复阻塞、补充持续价值、事件提醒、服务恢复、个性化内容或必要权益。召回实验必须保留自然回流对照，并把成功定义为恢复核心行为且在后续窗口没有立即再次沉睡。

## 判断规则

| 信号 | 可形成的判断 | 不能直接下的结论 | 下一步 |
|---|---|---|---|
| 整体留存下降、分群内稳定 | 用户结构发生变化 | “产品变差” | 检查渠道、产品和新老用户占比 |
| 多个 Cohort 同一时点断崖 | 同期版本、供给、活动或口径变化优先 | “用户自然流失” | 建变更时间线并查异常事件 |
| 某渠道早期留存低 | 渠道匹配或承诺可能有问题 | “渠道一定无效” | 同窗比较激活、贡献和成本 |
| 核心行为下降早于流失 | 可作为预警候选 | 它是流失原因 | 做前置干预实验和误报检查 |
| 召回组回流高、对照也高 | 存在自然回流 | “召回活动有效” | 计算净增回流和增量贡献 |
| 回流只发生在领券/点击 | 召回未恢复核心价值 | “召回成功” | 观察核心行为和后续再留存 |
| 投诉、履约失败集中在流失前 | 服务恢复优先 | “加大发券” | 先解决失败并确认补救效果 |
| 低频用户未在短期回访 | 可能没有新机会 | “需要高频召回” | 改用机会留存和周期预警 |

阈值必须来自历史分布、业务机会、服务承诺或验证实验。没有依据时输出候选阈值和验证方法，不写固定天数或比例。

## 策略机制

### 1. 留存预防

- 在首次价值后连接第二次真实使用理由。
- 对完成失败、结果不清、供给不足和服务异常及时恢复。
- 围绕用户自定计划、交易/合同节点和需求事件提供提醒。
- 让用户看见进度、历史成果、未完成目标和持续价值。
- 对高风险用户先确认原因，再决定内容、服务、权益或产品动作。

### 2. 分层预警

| 状态 | 目标 | 机制 | 退出条件 |
|---|---|---|---|
| 轻微偏离 | 帮助恢复正常节奏 | 价值提醒、断点恢复、相关内容 | 恢复、无需求或退订 |
| 明显风险 | 找原因并修复障碍 | 人工关怀、服务恢复、路径帮助 | 问题解决、不可挽回或升级处理 |
| 沉默但可挽回 | 重新建立核心价值 | 新价值、场景化召回、必要权益 | 恢复核心行为或序列结束 |
| 已流失/低价值 | 控制成本与打扰 | 低频许可式触达或不触达 | 退订、拒绝或长期归档 |

### 3. 召回序列

按“原因 → 价值 → 行动 → 退出”设计，而不是连续加券：

1. 确认用户仍有需求和触达许可。
2. 告知与其历史行为相关的新价值、服务恢复或未完成事项。
3. 给一个低摩擦的恢复入口。
4. 仅在经济性允许且能解决真实障碍时使用权益。
5. 根据完成、未完成、拒绝、退订和失败原因分支。
6. 达到频控或无响应上限后停止。

### 4. 服务补救

因履约、质量、客服或技术故障流失时，先承认和修复问题，再说明补救；不能用营销话术绕过投诉。补偿与损失、责任和法规要求匹配，并追踪问题是否真正关闭。

### 5. 防二次沉睡

召回后立即连接一个能持续产生价值的下一步，观察至少一个后续机会窗口。只回来领权益、打开页面或完成一次低价值行为，不算稳定恢复。

### 6. 不召回策略

对无需求、低价值且成本高、明确拒绝、触达无授权、投诉未解决、欺诈风险或产品已不适配的用户，记录不召回原因和复核时间，不因“用户池规模”持续打扰。

## 指标与口径

```text
区间留存率 = 窗口内完成回访价值行为的 Cohort 用户数 / 成熟 Cohort 用户数
机会留存率 = 在需求机会出现时完成目标行为的用户数 / 出现机会的合格用户数
流失率 = 窗口内满足流失定义的用户数 / 窗口开始时的合格用户数
预警命中率 = 被预警且随后真实流失的用户数 / 被预警用户数
预警覆盖率 = 被提前预警的真实流失用户数 / 全部真实流失用户数
召回恢复率 = 完成召回目标行为的合格触达用户数 / 合格触达用户数
净增召回率 = 实验组恢复率 - 可比对照组自然恢复率
召回后留存率 = 恢复用户中在后续窗口继续完成价值行为的人数 / 恢复用户数
单位净召回成本 = 增量召回成本 / 增量恢复用户数
召回增量贡献 = 实验组贡献 - 可比对照组贡献 - 增量成本
```

主要指标选留存率、净增召回率或召回后留存率之一。预警模型同时报告命中、覆盖、提前量和分群表现，不能只报一个准确率。

护栏至少包括：投诉/退订、退款/取消、履约失败、触达疲劳、优惠蚕食、作弊、单位净召回成本、服务容量和对未流失用户的误伤。

## 护栏与停止条件

以下情况停止、回滚或转交：

- 召回增量贡献无法覆盖触达、权益、渠道和服务成本。
- 实验组恢复率上升，但对照组自然恢复相近或更高。
- 用户只领取权益，没有恢复核心行为或后续再次沉睡。
- 投诉、退订、退款、作弊或履约压力触及预设阈值。
- 高风险规则误伤大量正常用户，或不同关键人群表现显著不一致。
- 流失根因是未修复的产品、价格、供给、技术或服务问题。
- 用户已拒绝、退订、无授权、投诉未关闭或超过频控。
- Cohort 未成熟、身份未合并、事件缺失或对照污染，无法判断结果。

放量条件：存在可比净增、后续窗口仍留存、单位经济性成立、风险稳定、机制能按原因匹配且服务容量可扩展。

## 输出契约

1. **留存定义卡**：Cohort、起点、回访行为、窗口、机会口径、成熟和去重规则。
2. **Cohort 留存表/曲线说明**：分群、关键拐点、结构变化和数据限制。
3. **行为路径对比**：留存者/流失者的关键行为、最后位置和候选原因。
4. **流失原因树**：证据、责任域、反证、验证方法和优先级。
5. **预警规则表**：信号、基线、候选阈值、提前量、命中/覆盖、误伤和动作。
6. **召回资格矩阵**：价值、可挽回性、许可、成本、原因和是否进入召回。
7. **召回策略与序列**：人群、原因、价值主张、触发、渠道、频率、分支和退出。
8. **实验与经济性卡**：对照、自然回流、主要指标、护栏、成本、停止和放量条件。
9. **防二次沉睡方案**：恢复后的下一价值行为、后续窗口和负责人。

结论必须区分：留存问题、渠道质量问题、激活问题、产品/供给/服务问题、自然周期，或数据证据不足。
