# 精细化策略与实验

## 策略最小单元

每条策略必须完整：

```text
目标人群 + 当前障碍 + 目标行为 + 价值主张 + 触发时机 + 渠道内容 + 频率 + 指标 + 退出条件
```

如果只有“发券、推送、建群、做活动”，要求补全其余字段。

## 触达序列

| 顺序 | 触发 | 人群 | 内容目的 | 渠道 | 延迟 | 频控 | 成功条件 | 停止条件 |
|---:|---|---|---|---|---|---|---|---|

序列要随用户行为变化。用户完成目标、退订、投诉或进入其他状态后立即停止不相关触达。

## 实验卡

```text
决策问题：
假设：如果对 [人群] 采用 [唯一关键变化]，则 [主要指标] 会变化，因为 [机制]。
实验组：
对照组或反事实基线：
分流单位：
样本与最小检测效果：
实验周期：
主要指标：
护栏指标：
数据质量检查：
停止条件：
判定规则：放大 / 调整 / 停止
```

## 实验闸门

- 一次实验只改变一个主要机制；多个组件必须说明无法拆分的原因。
- 在触达前分组，避免用结果行为倒推实验组。
- 检查实验组和对照组是否同时受到其他活动污染。
- 样本不足时报告方向和不确定性，不写“显著提升”。
- 不能只看点击率；同时检查转化、退款、退订、投诉、毛利和履约。
- 预先写停止条件，避免看到有利结果后随意结束。

## 优先级

先判断而非机械打分：

- 影响：对业务结果的潜在贡献。
- 证据：根因和机制是否有支持。
- 可执行：数据、渠道、内容、权益和团队是否具备。
- 成本：现金、开发、权益、履约和机会成本。
- 风险：用户伤害、品牌、合规和反作弊。

高影响但低证据的策略先做小实验；高风险策略即使可能有效也不直接放大。

## 复盘卡

| 项目 | 内容 |
|---|---|
| 预期 | 原假设和判定标准 |
| 实际 | 主要与护栏指标 |
| 差异 | 方向、幅度和不确定性 |
| 证据 | 数据质量、样本、污染 |
| 根因 | 已验证与待验证解释 |
| 决策 | 放大、调整、停止 |
| 机制更新 | 下次要改的规则或数据 |
