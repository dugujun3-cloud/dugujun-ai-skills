# 新用户承接、激活与新手引导

## 适用问题与边界

用于处理新用户已经到达、注册、留资、加企微或完成首单前后，却没有快速感知核心价值的问题，例如：

- 下载或注册很多，完成关键行为的人很少。
- 新客领了权益却不使用、不下单或只使用一次。
- 新手流程步骤多、耗时长，用户不知道下一步做什么。
- 不同渠道激活率差异大，无法判断是渠道质量还是承接问题。
- 首单后没有走到第二个关键行为，0—3 单大量流失。
- 团队把打开、签到、领券或完成教程当作激活，但这些行为不能证明价值被感知。

本模块把激活定义为：**符合目标用户条件的新用户，在业务允许的观察窗口内，完成能够代表首次价值实现的行为，并获得可感知反馈。**

边界：

- 注册、授权、打开、签到、领券或观看教程只能是过程事件，除非有证据表明它本身就是产品价值。
- 首次价值行为由业务价值链和后续留存证据共同确定，不能照搬其他产品的“魔法时刻”。
- 产品不可用、供给不足、价格错误、支付失败、履约违约或合规限制属于跨团队问题，不能只靠运营触达弥补。
- 低频、长决策或 B2B 业务不强求短期高频回访；可把完成首次方案配置、关键人接入、首次交付验收等定义为阶段性激活。
- 没有对照或反事实时，只能说策略与激活变化同时发生，不能声称产生增量。

## 最少输入

至少获得以下信息；缺少时先输出假设版诊断和补数清单：

| 输入 | 最低要求 |
|---|---|
| 产品与核心价值 | 用户为什么来，第一次可被用户感知的结果是什么 |
| 新用户起点 | 首次访问、留资、注册、加企微、开户或首购等明确事件 |
| 激活候选行为 | 1—3 个可能代表首次价值的行为及业务依据 |
| 观察窗口 | 从起点到激活允许多长时间，为什么符合决策或使用周期 |
| 新手路径 | 起点到首次价值的连续步骤、事件名称和顺序 |
| 基线数据 | 各步骤人数或用户级事件，至少能计算一步转化 |
| 分群字段 | 渠道、进入时间、产品类型或关键用户类型之一 |
| 当前干预 | 引导、内容、权益、人工服务、触达与频率 |
| 约束 | 触达许可、履约能力、预算、开发资源和风险限制 |

不要索取姓名、手机号等直接标识。使用匿名用户 ID 和事件时间即可。

## 诊断步骤

### 1. 校验口径和 Cohort 成熟度

确认起点、去重规则、事件顺序、观察窗口和数据时区。只比较已经走完同一观察窗口的 Cohort；未成熟 Cohort 单独标记，不与完整 Cohort 直接比较。

先排查：事件漏报或重复、跨端身份未合并、渠道标记丢失、机器人或内部账号、版本发布导致的埋点变化。

### 2. 定义首次价值

用以下四问筛选激活事件：

1. 用户完成后是否实际获得了核心结果，而非仅完成企业要求的步骤？
2. 该行为是否发生在用户可以接受的时间内？
3. 用户是否能感知结果已经发生？
4. 完成者在后续留存或价值行为上是否表现更好，且这种差异值得进一步验证？

输出一个主激活事件和必要前置条件。若多个行为必须组合完成，明确 `A → B` 的顺序和最长允许间隔。

### 3. 建立激活漏斗与时间分布

按真实顺序建立：

```text
合格新用户 → 理解价值 → 完成必要配置/授权 → 尝试核心动作 → 获得结果 → 感知结果
```

对每一步同时看：到达人数、步骤转化率、流失人数、完成耗时中位数和长尾。漏斗只显示“哪里掉”，路径回放、错误日志、客服/VOC 和访谈用于解释“为什么掉”。

### 4. 分群判断来源

至少按渠道或进入时间拆一层，再按产品类型、设备、地区、用户需求或版本选择必要维度。先判断差异来自：

- 用户不匹配或承诺与实际价值不一致。
- 路径摩擦、授权、配置、支付或等待时间。
- 供给、库存、内容、服务人员或履约不足。
- 用户缺少信任、理解、动机或明确下一步。
- 激励吸引了只领奖励而不需要产品的人。
- 数据口径或 Cohort 尚未成熟。

### 5. 找到可干预瓶颈

优先选择“损失规模大 × 接近首次价值 × 可被当前团队影响 × 能验证”的节点。不要只因为某一步转化率最低就选它；入口很小或不影响首次价值的步骤可能不是首要瓶颈。

### 6. 设计最小实验

一次只验证一个主要机制，例如减少一步、改变默认值、提前价值预览、增加结果反馈或在特定中断点触发帮助。保留对照或反事实基线，观察至少覆盖完整激活窗口。

## 判断规则

| 信号 | 可形成的判断 | 不能直接下的结论 | 下一步 |
|---|---|---|---|
| 注册上涨、激活率下降 | 新增结构或承接质量可能变化 | “新渠道一定差” | 按渠道做同窗漏斗和下游质量对比 |
| 单一步骤集中流失且错误率上升 | 路径或技术阻塞优先级高 | “发消息就能解决” | 查日志、回放和异常设备/版本 |
| 耗时长尾扩大、转化下降 | 等待、理解或人工处理可能阻塞 | “用户没兴趣” | 分解等待时间和主动操作时间 |
| 领券高、核心行为低 | 奖励与核心价值可能脱节 | “优惠力度不够” | 比较领奖与未领奖用户的后续质量 |
| 完成候选行为者后续留存更高 | 它是激活候选行为 | 它导致了留存 | 控制进入来源和时期，做引导实验 |
| 所有分群在同一步骤同时下降 | 共性产品、供给或口径问题优先 | “某类用户质量差” | 检查版本、埋点、供给和同期变更 |
| 低频业务短期不回访 | 可能尚未出现下一次需求机会 | “已经流失” | 改用机会窗口和里程碑完成率 |

首次价值无法定义、事件顺序不可靠或供给无法履约时，先停止激活活动设计，转为定义口径、补埋点或修复交付。

## 策略机制

### 1. 预期对齐

让渠道承诺、落地页、新手首屏和实际交付描述同一个价值。对只被奖励吸引、需求不匹配的人群，不继续用更强补贴追求表面激活。

### 2. 路径减阻

- 删除首次价值前非必要的注册、授权、配置和信息填写。
- 能延后的信息延后收集；能预填的字段在获得许可后预填。
- 在用户中断的位置提供恢复入口，避免重新开始。
- 对不可删除的合规步骤解释原因、预计耗时和完成后的价值。

### 3. 单一下一步引导

每个阶段只给一个与当前障碍匹配的主要行动。新手引导优先让用户完成核心动作，不一次讲完全部功能。完成后立即展示结果、进度或下一次使用理由。

### 4. 分支式承接

按真实行为触发，而非按固定日历群发：

| 用户状态 | 目标 | 可选机制 | 退出条件 |
|---|---|---|---|
| 未开始关键步骤 | 解释价值并降低第一步成本 | 场景化示例、价值预览、人工答疑 | 开始、拒绝或超出窗口 |
| 中途退出 | 恢复未完成任务 | 断点续办、错误修复、必要提醒 | 完成、失败原因已确认或退订 |
| 已完成但未感知结果 | 强化结果反馈 | 完成确认、结果解释、使用建议 | 用户确认或进入下一阶段 |
| 已激活 | 连接下一关键行为 | 使用计划、第二次任务、服务承接 | 进入活跃/留存模块 |

### 5. 0—3 单或早期里程碑

交易业务把首单、第二单、第三单分别当作不同状态；非交易业务改为第一次、第二次、第三次核心使用或交付里程碑。每一步重新判断需要、供给、信任和使用周期，不默认继续加大优惠。

### 6. 人工与自动化协同

自动化处理高频、规则清晰的提醒；高价值、复杂配置、异常失败或长决策用户进入人工支持。人工介入必须有优先级、服务容量和退出规则。

## 指标与口径

```text
激活率 = 观察窗口内完成激活事件的合格新用户数 / 合格新用户数
步骤转化率 = 完成下一步骤的用户数 / 到达当前步骤的用户数
首次价值时间 = 激活事件时间 - 新用户起点时间
激活后留存率 = 激活 Cohort 中在约定后续窗口完成回访行为的人数 / 激活人数
激活成本 = 可归因的承接与激励成本 / 激活用户数
增量激活率 = 实验组激活率 - 可比对照组激活率
```

主要指标从激活率、首次价值时间或增量激活率中选一个。诊断指标包括步骤转化、错误率、等待时间和人工介入率。

护栏指标至少选择：投诉/退订、退款/取消、履约失败、作弊或异常行为、后续留存/贡献、人工服务超载。激活窗口、分母和去重规则必须写进指标字典。

## 护栏与停止条件

出现以下任一情况，暂停、回滚或降级方案：

- 投诉、退订、退款、错误或履约失败触及预先约定阈值。
- 激活率提高但后续留存、目标转化或贡献明显恶化，疑似伪激活。
- 增量激活带来的贡献无法覆盖增量激励、渠道和服务成本。
- 目标行为可被刷量、代做或重复触发，且尚无去重和反作弊规则。
- 实验组与对照组口径、渠道或观察窗口不可比。
- 主要瓶颈属于产品、供给、价格、法务或技术故障，运营动作无法修复。
- 用户明确拒绝、退订、完成激活或超出有效窗口后仍被持续触达。

放量仅在主要指标改善、护栏未恶化、下游质量可接受、资源可承受且至少完成一个完整观察窗口时考虑。没有统计检验条件时，只给方向性结论和下一轮验证。

## 输出契约

必须输出以下内容，未知项明确标注：

1. **激活定义卡**：合格新用户、起点、主激活事件、前置条件、窗口、业务理由、证据强度。
2. **新手路径漏斗**：步骤、人数、转化、耗时、主要流失、数据质量问题。
3. **分群差异表**：渠道/时期/关键人群的激活与下游质量。
4. **瓶颈证据表**：事实、推断、候选原因、反证和补数动作。
5. **承接策略表**：人群状态、障碍、目标行为、机制、触发、渠道、频率、退出条件。
6. **最小实验卡**：假设、唯一变量、实验/对照、周期、主指标、护栏、停止和判定标准。
7. **7 天动作与 30 天机制**：立即修正、验证动作、系统建设、负责人和依赖。

交付结论必须明确：当前是渠道质量问题、承接问题、产品/供给问题、数据问题，还是证据不足。
