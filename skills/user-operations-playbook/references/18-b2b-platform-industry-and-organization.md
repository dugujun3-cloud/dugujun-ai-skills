# B2B、平台、行业适配与组织治理

用于回答“B 端客户如何激活、续约和增购、双边平台该先运营哪一侧、通用方法怎样适配行业、用户运营项目如何分工和预算、VOC 与服务问题如何闭环”。本模块提供跨场景诊断与交付框架，不用 C 端触达逻辑替代组织客户、供需平台或复杂履约问题。

## 1. 适用问题与边界

适用于：

- B2B/SaaS 的账户、联系人、决策链、部署、采用、客户成功、续约和增购。
- 双边或多边平台的供给、需求、匹配、流动性、质量、信任和跨边网络效应。
- 电商、内容、教育、本地生活、低频交易、门店、SaaS 等业务的运营方法适配。
- 运营目标、项目组合、预算、RACI、跨部门依赖、风险和复盘治理。
- VOC、NPS/满意度、服务故障、投诉、补救与闭环。

不直接替代：

- 产品路线、销售签约、合同、财务预算、法务合规、供给采购和服务交付决策。
- B2B 定制开发、平台算法、动态定价或容量调度的工程方案。
- 只凭运营指标对行业、平台或组织做战略承诺。
- 把 NPS、满意度、会议次数或工单关闭数直接当续约和业务价值。

## 2. 最少输入

### 2.1 B2B

- 账户、合同、产品和收费模式。
- 决策者、采购者、管理员、使用者、财务/法务和反对者等角色。
- 生命周期阶段：线索、试用、部署、激活、采用、价值实现、续约、增购或流失。
- 关键功能/流程使用、业务结果、服务记录、合同到期和风险信号。
- 客户价值、服务成本、负责人、承诺与不可控依赖。

### 2.2 平台与行业

- 平台各侧是谁，各自供给什么、需求什么、如何完成匹配和交易。
- 地域/品类/时间等最小市场单元，供需量、质量、等待、匹配和履约。
- 行业频次、决策单位、价值兑现周期、供给约束、监管和数据边界。
- 当前主瓶颈属于需求、供给、匹配、信任、价格还是履约。

### 2.3 组织、预算与 VOC

- 目标、项目、指标、基线、预算口径、资源和依赖。
- 决策者、负责人、执行者、协作方、咨询/知情方。
- 用户反馈来源、发生场景、影响范围、严重性、工单和业务结果。
- 可承诺的服务标准、补救权限、升级路径和复盘机制。

## 3. 诊断步骤

### 3.1 先识别运营对象

| 场景 | 主对象 | 不能混淆 |
|---|---|---|
| B2B | 企业账户及其合同/业务结果 | 联系人、席位、账号不等于账户 |
| 双边平台 | 一个最小市场中的供需双方及匹配 | 全站总量不等于局部流动性 |
| C 端/家庭 | 个人、账户或家庭决策单元 | 设备、会员卡、订单不等于人 |
| 门店/本地服务 | 用户—门店—服务时段组合 | 注册量不等于可履约需求 |

如果主对象不清，先建立实体和关系表，再做分层、指标和策略。

### 3.2 B2B 账户诊断

沿以下链路检查：

```text
ICP/目标账户 → 合格线索 → 多角色共识 → 试用/签约 → 部署
→ 首次业务价值 → 核心流程采用 → 价值实现 → 续约 → 增购 → 推荐
```

每个账户至少检查：

1. **价值匹配**：要解决的业务问题、成功标准和不可控依赖。
2. **角色地图**：经济买方、决策者、管理员、使用者、采购/技术/法务、拥护者和反对者。
3. **实施状态**：数据/配置、集成、培训、权限和上线里程碑。
4. **采用状态**：关键角色覆盖、核心功能深度、工作流嵌入和使用障碍。
5. **价值证据**：基线、结果、客户认可、证据来源和归因边界。
6. **关系风险**：单一联系人、关键人离职、组织调整、预算和竞品。
7. **服务经济性**：合同价值、服务成本、定制负担和健康度趋势。

不得用登录频次单独定义账户健康。低频产品可能按需使用即健康，高登录也可能来自故障排查或重复操作。

### 3.3 建账户健康度

健康度用于排队和调查，不用于自动宣判续约。建议按业务选择信号：

| 维度 | 候选信号 | 解释边界 |
|---|---|---|
| 价值匹配 | 成功标准、业务场景、需求变化 | 需客户和内部共同确认 |
| 实施 | 里程碑、集成、数据和培训 | 延期原因可能在双方 |
| 采用 | 核心功能、角色覆盖、流程深度 | 频次需按产品场景解释 |
| 成果 | 客户认可的效率、收入、风险或质量结果 | 不把相关性写成产品贡献 |
| 关系 | 关键人参与、多角色共识、管理层支持 | 会议多不等于关系好 |
| 服务 | 工单、故障、承诺和解决体验 | 关闭工单不等于问题解决 |
| 商务 | 到期、预算、采购、合同和付款风险 | 需销售/财务共同确认 |

每项保留原始证据、更新时间、负责人、置信度和人工备注。阈值由历史续约结果、产品周期和服务资源验证，不使用通用固定分数。

### 3.4 续约与增购诊断

续约先问：客户是否实现并认可约定价值，而不是先发优惠。

续约风险按原因拆分：价值未实现、采用不足、服务故障、关键人变化、预算/采购、竞争替代、产品缺口、业务收缩或证据缺失。每类匹配不同负责人和动作。

增购必须同时满足：

1. 新场景、席位、模块或业务单元存在真实需求。
2. 当前合同的核心价值已得到验证，重大服务问题已解决。
3. 新方案的价值、实施成本、使用者和成功标准明确。
4. 不以制造使用限制、隐藏功能或不必要复杂度迫使升级。

续约风险组合至少同时展示账户数和收入暴露，避免大客户被平均值掩盖：

```text
到期 ARR = 观察窗内到期账户的合同经常性收入
风险 ARR = 到期 ARR 中已满足已验证风险条件的金额
风险集中度 = 最大若干风险账户 ARR / 全部风险 ARR
```

若要计算“预期风险 ARR”，概率必须来自可回测的历史或明确情景，不得把健康分直接当续约概率。小样本时使用高/中/低情景和证据等级，不输出伪精确概率。

续约倒排不使用统一固定天数，围绕每个账户的真实采购决策日安排：

| 里程碑 | 必须回答 | 产物 | 未满足时 |
|---|---|---|---|
| 成功标准确认 | 客户为何购买，谁认可结果 | 成功标准与基线 | 暂停泛培训和报价 |
| 采用与障碍 | 哪个角色、工作流、依赖受阻 | 采用恢复计划 | 升级产品/实施/服务 |
| 价值证明 | 哪些结果已实现且可核验 | 价值报告/QBR | 标明证据缺口 |
| 风险与反对点 | 产品、服务、关系、预算、采购或竞争 | 风险清单与 Owner | 不猜价格是主因 |
| 商业方案 | 范围、价格、期限、条款和交换条件 | 审批后的方案 | 不做无条件让步 |
| 决策与交接 | 谁在何时决定，未续约如何处理 | 决策记录/流失复盘 | 停止无效追单 |

多角色核验问题按角色选择，不收集无关个人信息：

- 使用者/管理员：核心任务、阻塞、替代流程、近期变化和支持需求。
- 业务负责人/拥护者：原目标、结果证据、未实现价值和内部推广阻力。
- 经济买方/采购：决策标准、预算、采购时间、风险、替代方案和真实反对点。
- 服务/实施团队：未兑现承诺、反复工单、定制负担和客户确认状态。

价值报告或 QBR 至少包括：客户目标与基线、采用里程碑、已实现结果及证据边界、未解决风险、双方行动、负责人和下一决策日期；会议次数和幻灯片完成不算价值实现。

### 3.5 双边平台诊断

按最小市场单元建立闭环：

```text
需求到达 → 可见供给 → 匹配/响应 → 成交/接受 → 履约 → 评价/复用
供给加入 → 可服务状态 → 获得需求 → 接单/响应 → 履约 → 收益与留存
```

分别检查：

- **规模**：双方数量是否达到基本可用，但不把注册当可服务供给或有效需求。
- **密度**：在具体地域、品类、时间和价格带中是否相遇。
- **流动性**：需求能否在可接受时间找到合格供给，供给能否获得合理机会。
- **质量**：匹配相关性、成交、取消、履约、退款、投诉和复用。
- **信任**：身份、评价、担保、售后、违规和争议处理。
- **经济性**：双方获客、激励、补贴、抽佣、服务与履约成本。

先改善约束侧，但不能只优化一侧指标。例如增加供给若没有有效需求，会降低供给收益和留存；补贴需求若供给不足，会扩大等待和投诉。

平台干预可能改变同一市场里其他参与者的结果，用户级 A/B 不能默认满足互不干扰。验证需求刺激、供给补贴、排序或价格机制时：

- 先定义可相对独立的最小市场，并说明地域、品类、时段、价格带和跨市场流动。
- 按问题选择市场簇随机、不同饱和度实验或 switchback；预先定义清洗期、污染、同期变化和成熟窗口。
- 同时估计被干预对象的直接效应、未被干预对象的溢出效应和整个市场的系统净效应。
- 测量供给弹性：新增需求能带来多少可用供给、等待和成本变化；不能假设供给无限。
- 检查补贴退出后的交易、价格预期、双侧留存和贡献毛利，避免把短期流动性买成长期依赖。
- 独立市场或周期不足时，不声称平台级因果，只做受限试点并保留回滚。

### 3.6 行业适配

不要复制行业“最佳实践”，先填写适配卡：

| 维度 | 诊断问题 | 对策略的影响 |
|---|---|---|
| 需求频次 | 自然需求多久发生，是否受季节/事件驱动 | 触达、留存和召回口径 |
| 决策单位 | 个人、家庭、企业还是多角色 | 身份、内容和决策周期 |
| 首次价值 | 用户何时真正获得价值 | 激活定义和承接动作 |
| 价值兑现 | 即时、长期、结果型还是过程型 | 指标窗口和证据 |
| 供给/库存 | 是否稀缺、地域化、时段化或不可存储 | 放量、活动和履约护栏 |
| 毛利/现金流 | 成本何时发生、何时回收 | CAC、补贴和回收期 |
| 信任/风险 | 决策风险、退费、质量、安全和监管 | 内容、服务和合规 |
| 渠道/触点 | 用户在何处形成需求和完成交易 | 获客、私域和归因 |
| 数据成熟 | 关键结果多久成熟、能否回传 | 实验周期和领先指标 |

典型适配判断：

- 低频交易不以日活作为默认目标，重点看需求时点识别、信任、线索质量、成交和推荐。
- 订阅/SaaS 重点看首次价值、采用深度、成果、续约和服务成本。
- 内容业务区分消费、创作和社区角色，不能只追总时长。
- 电商同时检查流量、商品、价格、库存、履约和复购，不用触达修复供给问题。
- 本地生活按地域和时段看供需密度、到店/履约和门店差异。
- 教育或长期服务需区分购买、参与、学习/服务过程和结果，不能把完课或签到直接当效果。

### 3.7 组织与项目诊断

先建立目标—项目—指标—责任链：

```text
业务目标 → 用户问题 → 运营杠杆 → 项目组合 → 指标/护栏
→ 预算与资源 → RACI → 依赖与风险 → 节奏 → 复盘/停止
```

项目进入排期前必须回答：

1. 解决哪个用户问题，证据是什么？
2. 影响哪个业务结果和目标行为？
3. 当前基线、反事实和成熟窗口是什么？
4. 现金、权益、开发、内容、销售/客服和履约成本是什么？
5. 谁最终负责，依赖谁，冲突由谁裁决？
6. 不做的机会成本是什么，何时停止？

### 3.8 VOC 与服务补救

反馈链路：

```text
反馈/投诉 → 身份与场景 → 主题 → 严重性 → 影响范围
→ 事实核验 → 责任归属 → 即时补救 → 根因修复 → 用户确认 → 复盘
```

区分：单次情绪、重复体验问题、系统性缺陷、安全/合规事件和未知。VOC 是问题线索，不自动代表总体用户；要结合行为、工单、交易、退款、流失和样本结构验证。

NPS/满意度必须说明题目、量表、触发时点、邀请人群、响应率和样本偏差。分数变化可用于监控，不能单独证明某个动作导致续约或增长。

## 4. 判断规则

### 4.1 B2B 动作优先级

- 价值未定义：先和客户确认成功标准，不做泛培训或续费促销。
- 部署未完成：先解依赖、数据、权限和流程，不用登录提醒代替实施。
- 采用不足：定位角色、场景和路径障碍，按工作流而非功能列表辅导。
- 价值已实现但未感知：建立可核验的价值报告和多角色沟通。
- 服务故障未解决：先恢复和补救，再讨论续约或增购。
- 高健康且有真实新需求：才进入增购发现与小范围验证。

### 4.2 平台先运营哪一侧

根据最小市场中的约束判断：

- 有需求无可用供给：优先供给招募、可服务化、质量和响应。
- 有供给无有效需求：优先需求获取、需求质量和匹配分发。
- 双方都有但不成交：查匹配、价格、信任、响应和产品路径。
- 成交但履约差：停止扩量，优先质量、容量、规则和服务补救。
- 依赖补贴才活跃：核算增量、边际成本和补贴退出后的留存。

没有地域/品类/时间切片时，不根据全站总量判断约束侧。

### 4.3 预算与组织判断

- 先保护必须履约、安全、服务和数据基础，再分配增长实验预算。
- 高影响低证据项目先小实验，不直接获得大预算。
- 预算同时受样本、反馈周期、最小投放门槛、产能和止损限制，不能机械平均分配。
- 没有单一 accountable 负责人、跨部门依赖未承诺或数据不可测的项目不进入全量执行。
- 资源冲突由明确决策者按业务目标裁决，不靠会议次数解决。

### 4.4 服务补救判断

优先级由伤害严重性、影响范围、持续时间、可逆性和监管/安全风险决定。先止损和恢复，再解释原因；只关闭内部工单、未验证用户问题已解决，不能视为闭环。

## 5. 策略与实施

### 5.1 B2B 客户成功计划

| 字段 | 内容 |
|---|---|
| 账户与合同 | 范围、周期、价值和服务成本 |
| 成功标准 | 客户认可的业务结果、基线和证据 |
| 角色地图 | 角色、诉求、影响、关系和负责人 |
| 里程碑 | 部署、首次价值、采用和价值复盘 |
| 健康信号 | 原始证据、趋势、置信度和风险原因 |
| 动作 | 对谁、解决什么、何时、负责人和退出 |
| 续约/增购 | 条件、证据、依赖、反对点和决策日期 |
| 风险 | 服务、产品、关系、商务和外部变化 |

账户组合附表：

| 账户 | 到期/决策日 | ARR 暴露 | 风险原因与证据 | 可挽回性 | 下一里程碑 | R/A | 停止条件 |
|---|---|---:|---|---|---|---|---|

### 5.2 双边平台运营卡

| 最小市场 | 约束侧 | 需求质量 | 可用供给 | 匹配/等待 | 成交/接受 | 履约 | 复用 | 双侧经济性 | 动作与停止 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|

每个实验同时定义一侧主要指标和另一侧护栏，避免把损失转移给另一侧。

平台实验附表：

| 实验单元 | 干预/饱和度 | 对照/切换 | 直接效应 | 溢出效应 | 系统净效应 | 供给弹性 | 退出后质量 | 污染/停止 |
|---|---|---|---|---|---|---|---|---|

### 5.3 RACI 与项目卡

| 项目 | 用户问题 | 目标/指标 | R 负责执行 | A 最终负责 | C 咨询 | I 知情 | 预算/产能 | 依赖 | 风险 | 停止 |
|---|---|---|---|---|---|---|---|---|---|---|

R 可以多人，A 只能明确一个。RACI 不替代决策机制；同时写清升级条件、裁决人和响应时限。

### 5.4 VOC 闭环与服务补救卡

| 字段 | 内容 |
|---|---|
| 事实 | 用户、场景、时间、承诺、实际和证据 |
| 影响 | 严重性、范围、持续、可逆和风险 |
| 即时动作 | 止损、恢复、告知、替代方案和负责人 |
| 补救 | 与实际损失和责任匹配的方案及审批 |
| 根因 | 人、流程、系统、政策、供给或未知 |
| 修复 | 预防动作、验证指标、期限和负责人 |
| 闭环 | 用户确认、未解决原因、复发监控 |

## 6. 指标

### 6.1 B2B 与客户成功

- 账户级部署、首次价值、核心流程采用和关键角色覆盖。
- 客户认可的业务结果、价值证明覆盖和成熟度。
- 健康度各维度趋势、风险账户、恢复和误报/漏报。
- 账户留存、合同续约、收入续约、流失、增购和收缩。
- 实施时长、服务成本、工单复发、承诺兑现和客户确认解决。

续约率需说明账户还是收入、到期 Cohort、合同周期和收缩/增购处理；不能混合未到期账户。

### 6.2 双边平台

- 双侧有效新增、可服务供给、有效需求和最小市场覆盖。
- 匹配率、响应/接受、等待时间、成交、取消和履约。
- 供给利用/收益、需求成功、复用和双侧留存。
- 质量、退款、投诉、作弊、争议和安全事件。
- 双侧 CAC、激励、补贴、贡献毛利和边际经济性。
- 市场级直接效应、溢出效应、系统净效应、供给弹性和补贴退出后的价格/留存变化。

### 6.3 组织、项目与 VOC

- 目标结果、里程碑、预算消耗、产能、依赖延期和停止项目。
- 项目组合中已验证、待验证、无效和高风险项目占比。
- VOC 覆盖、主题趋势、严重事件、首次响应、恢复、复发和用户确认解决。
- NPS/满意度的样本、响应、分布和分群差异，以及与行为结果的描述性关系。

## 7. 护栏

- B2B 账户数据与联系人个人数据分开治理，只采集履约和服务所需信息。
- 客户成功不承诺无法控制或无法验证的业务结果；价值报告保留基线和归因边界。
- 平台增长同时保护供需双方的质量、安全、收益、公平和申诉权。
- 不用补贴、排序或流量处罚迫使一侧接受不可持续条件。
- 行业适配遵守具体业务的消费者权益、资质、安全、隐私和合同边界；不输出未经核验的法律结论。
- 服务补救不要求用户放弃合法权利，不用封口、删评或歧视性待遇换取结案。
- RACI、预算和健康分数不替代负责人判断，关键决策保留证据与审批。
- 不引用知识库或第三方案例中的未核验品牌数字、行业阈值和固定时间表。

## 8. 停止条件

出现以下任一情况，停止扩量、续约推进、增购、自动处罚或项目执行：

- 客户成功标准、平台主对象、最小市场或指标口径尚未定义。
- 重大产品、供给、履约、安全、服务或合规问题尚未止损。
- B2B 账户重大风险仅由单一联系人或单一使用指标推断，证据不足。
- 平台一侧增长导致另一侧等待、收益、取消、投诉或安全风险突破护栏。
- 预算、服务成本、边际补贴或定制负担突破经批准上限。
- 项目没有 accountable 负责人、关键依赖未承诺或结果无法测量。
- VOC 显示重复系统性问题，补救完成但根因没有修复。
- 数据或反馈样本偏差足以改变行业、续约或服务结论。

## 9. 输出契约

B2B、平台、行业或组织任务默认输出：

1. 场景类型、主运营对象和适用边界。
2. 业务目标、用户/账户问题、证据和未知。
3. B2B 账户链路或平台双侧最小市场诊断。
4. 行业适配卡与不适用的通用假设。
5. 客户成功计划、双边平台运营卡或 VOC 补救卡。
6. 指标字典、成熟窗口、基线和因果边界。
7. RACI、预算、产能、依赖和风险台账。
8. 7 天验证动作、30 天机制建设和停止条件。
9. 需要转交产品、销售、财务、法务、数据、供给或服务团队的事项。
