# 运营问题定义与诊断基础

## 目标—行为—动作—指标

按四层建立链路：

| 层级 | 要回答的问题 | 示例类型 |
|---|---|---|
| 业务目标 | 为什么要解决 | 收入、毛利、续费、留存 |
| 用户行为 | 用户要发生什么变化 | 完成核心行为、复购、推荐 |
| 运营动作 | 如何影响行为 | 引导、内容、权益、触达、服务 |
| 验证指标 | 如何判断有效 | 转化率、迁移率、增量毛利、投诉率 |

动作无法映射到行为和指标时，不进入优先计划。

## 问题定义卡

```text
目标用户：
生命周期阶段：
异常指标及口径：
观察周期：
对照基线：
偏差：
业务影响：
已知证据：
未知变量：
可控范围：
```

没有基线时不要承诺提升幅度。先补历史、同群组、同渠道或实验对照。

两个指标同步变化时不要直接写根因。先检查：指标定义是否变化、Cohort 是否完整成熟、渠道组合是否变化、产品或运营是否同期变更、差异是否集中在特定人群。只有完成这些检查，才能提高某个解释的置信度。

## 指标树

从业务结果向下拆：

```text
业务结果
├── 用户规模
├── 转化或付费效率
├── 频次与留存
├── 客单、毛利或贡献
└── 获客、权益、履约和服务成本
```

把指标分为：

- 结果指标：收入、毛利、LTV、续费。
- 过程指标：激活、留存、复购、迁移。
- 诊断指标：渠道、路径、触点、群组差异。
- 护栏指标：退款、投诉、退订、触达成本、权益成本。
- 虚荣指标：无法证明后续质量的曝光、发送、加粉或签到。

## 瓶颈优先级

按以下因素排序，不机械求总分：

1. 对业务结果的影响规模。
2. 证据强度和问题确定性。
3. 是否能被当前团队影响。
4. 验证速度和资源成本。
5. 用户伤害、合规和履约风险。

先处理大损失、高证据、可验证的节点。产品价值和履约问题必须交还相应责任方，不用运营触达掩盖。

## 责任边界

输出运营、产品、市场、销售、客服和数据的责任与依赖。用户运营可以设计人群、路径和干预，但不能独自解决产品不可用、供给不足、价格错误或数据基础缺失。
