## 00_产品说明书.md

```markdown
# [对外名] · 产品说明书

对外名：[ ]
一句：[先看清状态，再谈选择] 领域改写，结构不改
废止：[旧名1] [旧名2]
知识真源：知识树_*.md
改动纪律：改动纪律.md。用户点什么改什么。

## 定位
品类：去[决定]前的路径诊断
给谁：[岁数/年限]，反复问[那一个决定]。不限岗位/行业，除非创造者点名要限。
干什么：按一条线写清状态、选择、……最后给总行动建议。
不干什么：不保证[结果1] / [结果2]。不替人编理想。
差别：别人先问你想成为谁。这里先问你现在什么样。

## 交付线
[模块1] → [模块2] → … → 诊断结果
选 A：走 […]
选 B：先过 [理想关]，再走 […]
两叉可同时配，主曲线只能有一条。

## 一句话 Offer
[时长] 校准。结束带走：今天那一个决定 + 总行动建议 + 一张 90 天动作单。不给五条出路。
机制：网页自测（获客）→ 90 天手册（会后）→ 一对一校准（高价）。

## 三层
1 网页：N 维情况表 + 总行动建议。默认免费。
2 顾问框架：会前问、会中按同一条线、收动作单。不发给客户。
3 手册：会后按模块做。

## 明确不做
- 不保证 [ ]
- 不把顾问自己的人生选项塞给客户
- 不把某一岗位/行业样本当默认结论
- 不公开部署，除非用户点头
```

## 改动纪律.md

```markdown
# 改动纪律
用户点什么，改什么。没点的，不改。
1. 不为凑字数、自我发挥改已定的名字、导航、题库、正文。
2. 一次只做被要求的事。
3. 已锁定的线不许换。
4. 咨询样本不是结论。
5. 改完只核被点名的面。
```

## 知识树

```markdown

## 第一性
用户要解决的不是「方向」。他要决定：下一份力气换什么。
1. 现在站哪
2. 现实里能走哪几条
3. 想去哪，合不合理

## 交付骨架
[与说明书同一条线，每段 3–8 句判断]

## 全库用了什么

|---|---|---|
```

## verdictOf

先匹配先赢。不要加权。

```text
1. 人已经动了，选择还没写清
2. 选择是空的，理想也是空的
3. 想离开主线，交货的话还说不清
4. 先把交换从「做完」改成「做成」
5. 先认清能独立交货的那一块
6. 心走了，人先把主线做完
7. 主线还在，先交出第二曲线第一笔货
8. 各维能对上，90 天只钉死一件事
```

每条总建议三段：现在卡在哪 / 这 14 天 / 90 天 + 杀停 + 明确不做。

## 会前问卷

先锁场（那一个决定），再按维要事实。顾问收到后先标：

- 缓冲红线
- 交货空
- 走哪一叉

不要用内部样本套他。

## 60 分钟

```text
0–5   锁场：那一个决定 + 希望带走的一个动作。对方倒履历就打断。
5–15  当前状态三把尺。红线当场冻结后面的「走」。
15–22 有哪些选择。标正在走 / 托盘 / 准备中。
22–35 选了主线：表现 + 去留规则 + 往上只补一层。
35–42 理想三截。写不出对象，外面那截先别走。
42–52 外面的选择 + 第二曲线。没有交货不算正在走。
52–60 总建议口述 + 填动作单。周一第一件事 2 小时内能做完。
```

## 怎么交给客户

付款后 12 小时：会前问卷。  
会后 24 小时：填好的动作单 + 手册全文。  
不发：知识树、Offer 卡、顾问手册、内部样本、废止旧文件。
