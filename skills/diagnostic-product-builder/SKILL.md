# 决策诊断产品构建器

把创造者的判断炼成可卖的诊断产品。方法来自一套已交付的「职场路径诊断器」，不是再发明方法论。

**产品资产是一条锁死的线和一张规则表。** 网页、咨询、手册都跑这条线。代码最不值钱。用户没点头之前，不写 HTML。

模板：`references/templates.md`  
对照表：`references/worked-example.md`

## 何时不用

| 用户其实要的 | 改走 |
|---|---|
| 单文件问答 / 测评 / 策略生成器，不卖咨询 | 同仓库 `expertise-to-tool` |
| 知识体系可视化 + 打分评估网页 | 停。那是百科站，不是决策诊断 |
| 把已有诊断器变成 Agent 给人聊 | 停。那是执行层，不是本 skill |
| 文章、课纲、人生规划长篇 | 停。那不是诊断产品 |
| 保证结果、代写简历、替人编理想 | 停。写进「明确不做」 |

接的信号：用户卡的是**一个决定**（走不走、做不做、留下还是换），不是「帮我找方向」。

## 硬规则（全程）

1. 先锁决定，后谈理想。顺序反了就整条线废。
2. 三层共用一条导航。网页改了线，顾问手册和客户手册必须一起改。
3. 维是离散状态，不是 0–3 分。打分会把诊断做成体检表。
4. 总建议查优先级表，禁止模型另写总标题。
5. 咨询样本不是结论。岗位样板、顾问自己的人生选项，不进客户可见页。
6. 页上不写出处、知识库、篇名、付费话术（获客页默认免费）。
7. 用户点什么改什么。没点的不改。旧名废止后进 `_archive/`。
8. 不公开部署，除非用户点头。

## 执行顺序

一次只推进一阶段。每阶段产出用户确认后，才进下一阶段。

### 0. 分流（2 分钟）

问清要的是不是「网页自测 + 咨询校准 + 手册」三层。  
只要网页且不卖咨询 → `expertise-to-tool`。  
三层都要 → 继续。

### 1. 锁那一个决定

向创造者要四句，一次一题：

1. 目标用户付费结束必须带走的那一个决定是什么？
2. 他打开产品的那一秒在愁什么？（真实场景，不是人群标签）
3. 明确不保证什么？
4. 谁不接？

写不出第 1 句，停。不准用「找到方向」「成为更好的自己」起盘。

产出：`00_产品说明书.md` 里的「定位 + 一句话 Offer + 明确不做」。模板见 `references/templates.md`。

### 2. 写下第一性三问

任何这类产品拆到不能再拆，只剩三问，顺序不能反：

1. **现在站哪**（状态：交换 / 能力 / 约束）
2. **现实里能走哪几条**（可走，不是想走）
3. **想去哪，合不合理**（理想最后谈）

领域词可换（职场→交换层；生意→现金流；健康→可动用的缓冲），顺序不换。

产出：说明书里的「交付线」。用户指定导航顺序后锁死，后续禁止重排。

### 3. 抽知识树（只读创造者授权的材料）

扫描创造者明确给出的文章、课、聊天记录、笔记。产出 `知识树_*.md`，必须有两列：

- 用了什么（进骨架）
- 没用什么（防止塞进产品）

上一版若只从某一类文章抽过，标出漏掉的层。  
页上、手册、问卷都不写出处。本文件只给内部看。

用户确认「这些进、那些不进」之后，才拆维。

### 4. 拆维：每维只量一件事

把交付线落成 7–10 个维。每维：

- 题干问**上周真实发生的事 / 写到哪了 / 第一句说什么**
- 不问「该不该」「想不想」「高不高」
- 正好 4 个离散状态（key + 一句人话）
- 一题只量一把尺

两叉规则写死：选 A 走哪些模块；选 B 必须先过哪一关；主曲线只能有一条。

产出：`fields` 表。用户逐题审：有没有问错、漏问、两题量同一件事。

### 5. 写规则库，再写总建议优先级

对每个维的每个状态写 8 格（禁止缺格）：

`title / show / prob / howto / today / week / q90 / pass`

要求：

- `show` 回引用户会选的那句原文
- `prob` 写「这种情况下不要做什么」
- `today` 2 小时内能做完
- 跨维硬规则（如缓冲不够 → 外面那条冻结）写进 `howto`，也写进总建议表

总建议用优先级表，不是加权分。先匹配的那条赢。每条总建议固定三段：现在卡在哪 / 这 14 天 / 90 天验什么 + 杀停 + 明确不做。

产出：`BANK` + `verdictOf`。用 5 个合成人走表，总标题必须稳定。对不上就改表，不改文案腔。

### 6. 铺三层（同一条线）

目录锁成这样：

```
产品名/
  00_产品说明书.md
  改动纪律.md
  知识树_*.md                 （内部）
  1_网页工具/诊断器.html
  2_咨询交付框架/
    01_Offer卡与边界.md
    02_会前问卷.md
    03_顾问手册与会中工作台.md
    04_90天动作单.md
    05_样本_*.md              （内部，不当默认结论）
  3_交付产品/
    00_怎么交给客户.md
    诊断器_90天手册.md
  _archive/                   （废止的旧名）
```

**网页（获客）**

- 总览先画出这条线，不要三问卡片糊弄
- 每段线一页讲解 + 最后一页情况表出结果
- 情况表 = `fields`；结果 = `verdictOf` 总标题 + 三段 + 每维 8 格
- 单文件 HTML，不接运行时大模型
- 结果页不跳转走掉
- 默认不写付费入口

**咨询（高价）**

- Offer：一场一个决定 + 总建议 + 90 天动作单。不给五条出路
- 会前问卷与网页维一一对应，另加「锁场」那一个决定
- 60 分钟按同一条线走，见模板
- 缓冲红线、交货空，上场先标

**手册（会后）**

- 章节顺序 = 导航顺序
- 每章：判断 + 作业 + 验收 + 杀停
- 不发知识树、Offer 卡、顾问手册、内部样本

### 7. 对拍再交付

三层对拍：

1. 网页总标题 = `verdictOf` 原文
2. 会前问卷能映射到同一组 key
3. 手册章节能指回同一条线
4. 样本不当默认人设
5. 客户可见文字无出处、无保证

本地预览网页。不部署，除非用户说部署。  
改动只动被点名的那一处。旧版改名进 `_archive/`。

## 验收

- [ ] 一句话决定写得出，不是「找方向」
- [ ] 交付线已锁，三层导航一致
- [ ] 知识树有「用了 / 没用」
- [ ] 7–10 维，每维 4 态，题干问事实
- [ ] BANK 每态 8 格齐，含否定性建议
- [ ] 总建议是优先级表，5 个合成人标题稳定
- [ ] 网页 / 顾问包 / 手册三套都在，内部文件不进客户包
- [ ] 改动纪律和废止旧名已写
