# 验收与复用审计

## 任务验收

逐项核对，不用一个“完成”覆盖不同状态：

1. **交付物**：目标文件、文本、分析或操作结果真实存在且可读取。
2. **内容**：关键事实、数字、结构、格式和用户原始判断没有被误改。
3. **验证**：执行了适合该任务的回读、解析、测试、复核或人工验收步骤。
4. **边界**：未授权的读取、外发、写入、覆盖、删除、发布和付费没有发生。
5. **验收**：只记录用户明确验收的范围；局部验收不扩大为整项任务验收。

## 复用审计

从以下五个维度判断是否值得沉淀：

| 维度 | 要回答的问题 |
| --- | --- |
| 重复性 | 用户是否会再次遇到同类任务，或已有第二个独立案例？ |
| 稳定性 | 哪些步骤和判断跨案例保持不变，哪些只是本次偶然？ |
| 输入契约 | 是否能清楚描述必需输入、可选输入和缺失输入的处理方式？ |
| 风险与自由度 | 哪些步骤可由模型判断，哪些必须脚本固定或人工批准？ |
| 可验证性 | 是否存在明确的完成证据、失败信号和回退方式？ |

## 成熟度状态

- `one_off`：当前做法高度依赖本次语境，没有值得复用的稳定结构。
- `candidate`：已提取触发条件、输入、流程、边界和验收，但证据主要来自单次或同源案例。
- `statically_validated`：Skill 结构和元数据通过静态校验；这不等于行为已经验证。
- `behaviorally_validated`：在相互独立的真实任务或无答案泄漏的前向测试中表现稳定，失败边界已记录。
- `accepted_for_use`：用户验收并授权安装或使用；这仍不等于已公开发布。

不要跳级，也不要把 `statically_validated` 写成“已实测可用”。

## Skill 候选输出

生成候选时包含：

1. 名称和一句话价值。
2. 触发语句与不应触发的场景。
3. 必需输入、可选输入和输出。
4. 核心流程、工具、权限边界和恢复方式。
5. 验收标准、已有证据、未知项和下一批测试用例。

将案例专属的人名、路径、金额、平台状态和临时模型版本留在案例记录，不写进通用 Skill 核心。易变配置放入按需读取的 reference。
