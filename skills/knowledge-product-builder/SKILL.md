# 知识资产产品化

手里已经有一堆判断、案例、方法和模板，但它们是散的——散在文章里、笔记里、聊天记录里。

本 Skill 负责把它们**组装成一件能独立交付的东西**。

## 定位

知识产品的**交付层执行器**。上游决定卖什么、卖多少；本 Skill 把东西装出来。

**不负责**：产品定位、验证、定价、获客（归上游）、平台上架与收款（归本人）。

## 组装流程

### 1. 锁定内容源与产品形态

先给**一个推荐候选**（含理由），不抛开放题让用户选。

产品形态对照：

| 形态 | 适合的内容 | 交付特点 |
| --- | --- | --- |
| 文档包 | 成体系的方法论、长文系列 | 最轻，改版成本低 |
| 模板包 | 可复用的表格、清单、话术 | 空表 + 示例双份 |
| Prompt 包 | 有稳定输出的提示词流程 | 要配输入样例和失败案例 |
| 课程模块 | 需要循序渐进的技能 | 要配练习与验收标准 |
| 小工具 | 有确定输入输出的判断 | 做成能跑的东西，见 `expertise-to-tool` |

### 2. 产品结构设计

定目录 / 模块 / 使用路径 / 交付形式。**使用路径必须能一句话说清**——说不清说明结构没想明白。

### 3. 组装

- **保真抽取**作者原文的判断、案例与数字，不改写、不稀释
- 模板做「空表 + 示例」双份
- 不写 AI 空洞话：每一段都要有具体判断或可执行动作

### 4. 质量闸门

- 交付物能**独立使用**——脱离原上下文也看得懂
- 案例真实可溯源，数字有出处
- 不虚构客户见证、不编造效果数据

### 5. 打包交付

源文件 + 交付形态 + 使用说明 + 验收清单。

## 手册类产品的额外流程

长手册（几千字到几万字）有它自己的节奏，实测有效的做法：

1. **先出大纲给用户审定**——章节结构 + 字数预算 + 每章要给的判断。审过才动笔，大纲里主动写清取舍
2. **分部撰写，分部分审**——写一部分发一部分，别一次甩全稿
3. **声口审三遍**——AI 味高发点：虚构场景（「一个运营负责人花了两周……」）、每节共用一个模子的工整结构、翻案腔（不是 A 而是 B）、成语收尾、抖机灵。案例与数据必须能追溯到原始素材或可核验来源
4. **格式三要素**——章节连续编号、小节内加粗小点、能用表格就不用文字堆
5. **加厚走真材实料**——从已有素材里挖可溯源案例，不注水
6. **合稿成单文件**——导入任何平台前检查字面量转义、去掉重复的顶级标题

## 交付物

- 产品包：源文件 + 交付形态 + 使用说明 + 验收清单
- 定价与获客材料**交回上游**，不在本 Skill 内做决策

## 闸门

- 引用案例必须真实可溯源；不虚构数据与客户见证
- **售卖、上架、收款动作由本人执行**，本 Skill 不代办
- 产出先落当前项目目录，不散落到别处
