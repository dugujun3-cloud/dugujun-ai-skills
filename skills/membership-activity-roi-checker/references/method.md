# 计算口径与证据边界

## 1. 先选结果，不先算 ROI

| 目标 | 主要结果 | 默认经济指标 |
|---|---|---|
| `reactivation_value` | 召回、复购、续费等成熟结果 | 增量净值、增量 ROI |
| `member_acquisition` | 有效新增会员 | 单位增量会员成本；有贡献价值时再算 ROI |
| `qualified_traffic` | 合格访问、咨询或到店 | 单位结果成本；默认不算 ROI |

一次活动只设一个主要结果。参与人数、券领取、消息点击和总 GMV 只能作为过程或观察指标。

## 2. 反事实

优先级：

1. `randomized_control`：同窗随机保留组。
2. `matched_control`：同窗匹配人群或分阶段对照。
3. `historical_baseline`：同定义、同长度观察窗的历史或自然基线。
4. `none`：没有反事实，只做描述。

不要比较不同购买周期、不同渠道结构、不同价格或不同成熟窗口的人群。若同期产品、价格、供给、履约或数据口径变化，写进限制。

## 3. 公式

```text
活动组结果率 = 活动组结果数 / 活动组覆盖人数
基线结果率 = 对照组结果数 / 对照组覆盖人数
或使用用户提供的可信历史基线

预期自然结果数 = 活动组覆盖人数 × 基线结果率
增量结果数 = 活动组结果数 - 预期自然结果数

活动组贡献价值 = 活动组净收入 - 活动组变动成本
基线贡献价值 = 同窗对照组贡献价值按活动组规模折算
或 活动组覆盖人数 × 可信历史人均基线贡献价值
增量贡献价值 = 活动组贡献价值 - 基线贡献价值

活动成本 = 权益 + 媒体/渠道 + 技术 + 额外人工 + 固定履约 + 欺诈及异常损失 + 其他增量成本
收益成本比 = 增量贡献价值 / 活动成本
增量净值 = 增量贡献价值 - 活动成本
增量净 ROI = 增量净值 / 活动成本 = 收益成本比 - 1
单位增量结果成本 = 活动成本 / 增量结果数
```

若暂时拿不到活动组贡献价值，可用「增量结果数 × 单个结果贡献价值」作为备选。单个结果贡献价值应扣除退款、商品或服务变动成本和随结果增长的履约成本。不要与 `costs.fulfillment` 重复扣除；后者只放不随单个结果重复计算的活动固定增量履约支出。发布结论前必须把 `double_count_checked` 标为 `true`。

收益成本比的盈亏平衡点是 `1`；增量净 ROI 的盈亏平衡点是 `0`。两者必须同时标注全名，不把任一口径笼统写成「ROI」。

## 4. 证据等级

| 等级 | 可说 | 不可说 |
|---|---|---|
| A | 对照条件下观察到增量差异 | 未检查污染、样本与执行偏差时宣称确定因果 |
| B | 匹配或分阶段比较支持某方向 | 活动是唯一原因 |
| C | 相对历史基线的估计 | 当前活动造成了变化 |
| D | 观察结果、总成本和单位观察成本 | 增量、因果和真实 ROI |
| E | 数据不足与补数项 | 继续或停止结论 |

## 5. 决策边界

- 用户没有提供业务阈值时，输出计算结果和 `compare_with_business_thresholds`。
- 任一隐私、合规、消费者权益或履约红线触发时，输出 `pause_and_investigate`。
- 增量结果不为正时，输出 `do_not_scale`，但不要自动归因到活动机制。
- 达到用户提供的全部阈值且护栏未触发时，最多输出 `eligible_for_small_scale`，仍需人工审批。
- 数据不成熟、成本不全或反事实失真时，输出 `evidence_insufficient`。
