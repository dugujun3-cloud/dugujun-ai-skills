# 一人公司端到端主控工作流

## 主控定位

本 Skill 在端到端任务中承担项目主控，而不是替代所有专项执行者。主控始终负责：

- 确认生活和资源约束、当前业务阶段与本轮唯一主决策。
- 维护项目状态、证据、产物清单、阶段闸门、用户验收和下一步动作。
- 只执行当前阶段需要的本地、可回滚工作；把专业执行路由给对应 Skill。
- 收回专项结果，检查文件、证据、边界和验收条件，再决定是否进入下一阶段。
- 区分计划、已准备、已批准、已执行和已核验；不把草稿或用户意向写成真实成交、发布或客户结果。

“贯穿全程”指主控不会在给出诊断和计划后退出，而是能在多轮任务中启动、续跑、回退、暂停、停止和完成项目。它不扩大外部操作授权，也不取代律师、税务师、真实客户、平台发布流程或产品工程专项能力。

## 统一阶段 ID

控制器的 `current_stage` 只使用以下 10 个阶段 ID，不得再创建 P0、P1 等同义阶段：

```text
00_scope_constraints
→ 10_positioning
→ 20_customer_evidence
→ 30_offer_mvp
→ 40_market_validation
→ 50_pilot_delivery
→ 60_pricing_economics
→ 70_acquisition_trust
→ 80_systemization_productization
→ 90_scale_transition_review
```

业务成熟度另用 `business_stage` 表示：`idea / validation / first_sales / delivery / systemization / transition / expansion`。工作流阶段和业务成熟度不可混为同一个字段，也不能因生成文件而自动提升成熟度。

## 状态转移图

```text
启动或恢复
  ↓
00_scope_constraints 立项与约束
  ↓
10_positioning 能力、定位与客户假设
  ↓
20_customer_evidence 客户问题与行为证据
  ↓
30_offer_mvp Offer、价格假设与 MVP
  ↓
40_market_validation 真实市场承诺与首批成交验证
  ↓
50_pilot_delivery 首批交付、结果与客户验收
  ↓
60_pricing_economics 定价、成本、容量与单位经济性
  ↓
70_acquisition_trust 可重复获客、信任与承接
  ↓
80_systemization_productization 系统化与产品形态分支
  ↓
90_scale_transition_review 规模、转全职、风险与周期复盘
  ├─ stop：停止并归档
  ├─ iterate：回到证据不足的最早阶段
  └─ continue/scale：维持运营并按周期复盘
```

早期招募和少量定向触达属于 `40_market_validation` 的验证手段；只有交付和经济性通过后，才在 `70_acquisition_trust` 建设可重复的获客系统，避免用内容放大未经验证的 Offer。

## 阶段执行通则

每次只执行一个当前阶段。开始前读取状态和 handoff；没有运行项目时才立项。每一阶段都按以下顺序工作：

```text
确认进入依据 → 核对输入与缺口 → 生成阶段产物
→ 自检 → 用户验收 → 更新证据与状态 → 设置下一阶段
```

每阶段必须定义：本轮唯一目标、必备输入、必备产物、成功信号、护栏、最大可接受损失、外部动作边界、验收条件、回退条件和停止条件。缺数据时可以补证，不得用假数字补齐闸门。

控制器的机器可检验产物以 `assets/workflow-stage-manifest.json` 为准。下列业务材料可以作为清单中对应 Markdown/JSON 产物的章节集中保存，不要求为了形式拆成更多文件。

## 00_scope_constraints：立项与约束

### 输入

- 用户当前想解决的主问题、已有项目或产品想法。
- 想要的生活、时间、现金、声誉、健康和家庭边界。
- 已有能力、案例、渠道、内容、关系、工具和产品资产。
- 用户允许写入的工作区位置；知识库只读边界固定有效。

### 必备产物

- `decision_brief.json`：项目目标、完成定义、主决策、已有资产和当前业务成熟度。
- `constraints.md`：生活/资源边界、不可做事项、最大投入和主要风险。
- `evidence_ledger.md`：事实、推断、假设、未知、证据来源和下一步补证。
- 控制器自动生成的 `workflow_status.json`、`handoff.md` 与 `events.jsonl`。

### 闸门

用户确认项目只解决一个主决策，约束、最大投入、完成定义和不做事项没有关键冲突后进入 `10_positioning`。目标仍是多个互相竞争的项目时，不得直接进入产品设计。

### 回退或停止

缺少会改变方向的生活/资源边界时，用 `block --owner user` 保存原因与恢复条件；项目违背硬边界或最大损失不可接受时停止或重写章程。

## 10_positioning：能力、定位与客户假设

### 输入

- 已验收的项目章程和资产清单。
- 可迁移能力的真实业绩、作品、案例与失败记录。
- 候选客户、场景、问题和现有替代方案。

### 必备产物

- 生活—商业对齐表。
- 能力—问题—人群矩阵。
- 候选方向比较、淘汰理由和本轮定位假设。
- 一个客户—场景—问题假设及待验证反证。

### 闸门

只保留一个本轮客户—问题假设；它符合生活边界、具有可接触对象和可验证行为。此处通过不代表市场成立，只代表可以进入 `20_customer_evidence`。

### 回退或停止

没有可信能力证据时回到资产盘点；候选客户不可触达或问题无法被观察时调整人群/场景；所有候选均违背硬边界时停止本项目。

## 20_customer_evidence：客户问题与行为证据

### 输入

- 已验收的客户—问题假设。
- 真实目标用户、已有行为数据、历史咨询记录或可执行的访谈/观察计划。

### 必备产物

- 客户纳入/排除条件。
- 访谈或观察计划、记录和证据账本。
- 问题频率、代价、替代方案、既有投入和购买角色判断。
- `go / weak-go / no-go` 结论及反证。

### 闸门

- `go`：行为证据足以进入 Offer/MVP 设计。
- `weak-go`：只允许一轮范围受限的补证实验，不得伪装为验证通过。
- `no-go`：不得进入完整 Offer 制作；回到 `10_positioning` 或停止。

闸门不硬编码访谈人数、搜索量或意向比例。依据应与本轮决策和样本来源相匹配。

## 30_offer_mvp：Offer、价格假设与 MVP

### 输入

- `20_customer_evidence` 的问题证据和客户原话。
- 用户可投入的交付时间、现金、容量、责任和风险边界。
- 客户价值、替代方案、支付路径和信任证据。

### 必备产物

- Offer 卡、MVP 实验卡和明确的不包含事项。
- 价格假设、付款方式与初始单位经济性变量。
- 交付 SOP、客户责任、接触点、验收和退出机制。
- 成功信号、护栏、最大投入、停止/调整/放大条件。

### 闸门

用户验收客户、承诺、范围、价格假设、交付责任、验收方法和止损条件。需要向外招募或销售时，仅把外部动作标为 `prepared`，不得因本阶段验收自动发送或发布。

### 回退或停止

Offer 无法对应已验证问题时回 `20_customer_evidence`；交付超出容量或责任不可接受时缩范围、换形态或停止；经济性信息不足时记录待补变量，不编造价格。

## 40_market_validation：真实市场承诺与首批成交验证

### 输入

- 已验收 Offer、MVP、价格假设和目标客户。
- 定向招募路径、最小信任材料、客户筛选和承接点。
- 需要的平台专项 brief 与当前规则。

### 必备产物

- 市场验证实验、客户筛选表、线索/预约/拒绝记录。
- 必要的招募内容、销售沟通提纲、异议和承诺边界。
- 专项 Skill 产物、自检和外部动作审批记录。
- 真实预约、定金/付款、资料提交或其他深层行为证据。
- 未成交原因和下一轮只调整的一个变量。

### 闸门

存在真实目标客户的深层行为或付费承诺，客户符合准入条件，范围和责任没有重大冲突，才进入 `50_pilot_delivery`。草稿、口头期待、点赞或模拟付款不能作为成交。外部发布、群发、投放或客户发送必须单独批准并核验。

### 回退或停止

没有询问时检查客户、问题、触达和表达，按证据回 `10_positioning`、`20_customer_evidence` 或 `30_offer_mvp`；有询问无成交时检查优先级、承诺、信任、风险和价格；出现欺诈、合规或不可接受客户风险时拒绝准入并升级人工处理。

## 50_pilot_delivery：首批交付、结果与客户验收

### 输入

- 已准入客户的目标、基线、责任、范围和排期。
- 已验收交付 SOP、专项工具和异常处理方案。

### 必备产物

- 客户 brief、交付计划、接触点和交付日志。
- 实际交付物、修改记录、工时、成本、返工和例外。
- 结果证据、客户反馈、客户验收或未达成记录。
- 售后、补救、退款或退出决定。

### 闸门

用户对本地交付产物的验收与真实客户对结果的验收分开记录。只有承诺范围内结果已核验，或未达成项和补救责任已清楚处理，阶段才可完成。

### 回退或停止

有付费无结果时停止新增招募，回 `30_offer_mvp` 修承诺/范围或留在本阶段修交付；重大投诉、安全、隐私或合规问题进入人工升级，不得用自动化继续执行。

## 60_pricing_economics：定价、成本、容量与单位经济性

### 输入

- `40_market_validation` 和 `50_pilot_delivery` 的真实付款、退款、结果、工时、成本、返工与创始人体验。
- 客户价值、替代方案、支付路径、容量和生活约束。

### 必备产物

- 实收、退款、渠道、工具/外包、直接成本和交付工时账本。
- 单客贡献、有效时薪、容量收入及固定/机会/生活成本说明。
- 最低可持续边界、当前测试价、目标价假设和敏感性变量。
- 保留、修复、调价、缩范围或停止决定。

### 闸门

真实结果和交付责任能支撑价格，贡献和容量不越过用户生活/风险边界；数据不足时只允许继续受控补证，不以营业额或一次大单替代经济性。

### 回退或停止

有结果但亏损/过载时回 `30_offer_mvp` 或 `50_pilot_delivery` 调范围、形态和流程；无结果时不得只涨价或加大获客；不可持续且无法调整时停止。

## 70_acquisition_trust：可重复获客、信任与承接

### 输入

- 已通过交付与经济性闸门的核心 Offer。
- 主渠道、承接点、可授权案例、客户语言和内容资产。
- 对应平台当前数据和专项 Skill 结果。

### 必备产物

- 发现—理解—相信—行动—结果—复购/推荐路径。
- 主渠道与承接点、内容/触达实验、成本和成熟窗口。
- 平台专项 brief、成品路径、自检和发布状态。
- 线索质量、预约、付款、结果和推荐的分环节证据。

### 闸门

渠道能产生可解释、可重复且质量可接受的客户行为；内容和案例授权真实；获客成本、交付容量与贡献匹配。草稿验收、发布、曝光和成交分别记录。

### 回退或停止

有流量无成交时依次回查人群、问题、Offer、证据、承接和交付风险；渠道放大导致交付失控时回 `50_pilot_delivery` 或 `60_pricing_economics`；不得用增加发布量掩盖上游问题。

## 80_systemization_productization：系统化与产品形态分支

### 输入

- 多轮交付中的重复问题、稳定流程、例外、结果、经济性和获客证据。
- 当前产品形态的维护成本、使用频率、标准化程度和人工判断要求。

### 必备产物

- 咨询、课程、产品知识库或 Web 应用分支规格。
- SOP、模板、质量闸门、人工验收、异常升级和版本策略。
- 试运行/内测结果、维护责任和停止/下架条件。

### 闸门

只有已验证、重复、可清楚验收的环节才能标准化或自动化。具体分支进入条件和产物见 `13-product-branch-playbooks.md`。

### 回退或停止

规则仍频繁变化时回人工/半人工交付；用户只需要低频查询时不开发 Web 应用；标准产品不能产生结果时回 `50_pilot_delivery` 重做交付验证。

## 90_scale_transition_review：规模、转全职、风险与周期复盘

### 输入

- 稳定获客、成交、交付、复购/推荐、贡献和容量证据。
- 客户、渠道、产品、平台和创始人依赖风险。
- 生活北极星、现金安全和最坏情况预案。

### 必备产物

- 周/月/季度商业实验和运营复盘。
- 产品组合、复购/推荐、风险和集中度台账。
- `iterate / stop / continue / scale` 决策。
- 转全职或扩张闸门；结论只能为继续验证、有条件推进或暂缓。

### 闸门

用户确认阶段决策且状态已更新。回退必须指定最早受影响阶段和只调整的变量；停止保存依据和可复用资产；转全职/扩张不能由单次成交、单月收入或一个爆款触发。

稳定运营不是自动完成状态。按周/月/季度复盘，根据证据决定维持、迭代、下架、转全职或扩张，重大变化允许回退到任一上游阶段重新验证。

## 完成定义

单次任务完成不等于一人公司项目完成。只有用户定义的项目目标已达成、当前阶段产物全部验收、没有未处理的高风险事项、外部动作状态真实、状态文件和 handoff 已更新，才可把当前项目标为 `completed`。
