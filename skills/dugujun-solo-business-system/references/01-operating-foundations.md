# 总控、生活约束与阶段诊断

## 决策顺序

始终按以下顺序工作：

```text
想过的生活与硬边界
→ 可承受的时间、现金和风险
→ 可迁移能力与可信证据
→ 客户问题与现有替代
→ 最小付费闭环
→ 稳定交付与定价
→ 获客、复购和转介绍
→ 标准化、AI、外包和扩张
```

不要从工具、公司主体、品牌名、网站、课程目录或多平台矩阵起步。

## 生活北极星

先把愿景改写成可检查的普通工作日：

- 希望每周工作多少时间，哪些时间必须留白？
- 需要达到什么收入底线，允许多大波动？
- 哪些客户、交付、沟通方式或价值观不可接受？
- 健康、家庭、关系、地域和声誉有哪些硬边界？
- 用户想要的是高增长、高自由、稳定、小而美，还是未来组建团队？这些目标不能默认兼得。

输出“生活—商业对齐表”：理想状态、当前状态、偏差、不可接受代价、设计约束。商业模式必须服从这些约束，而不是用收入掩盖失控的生活。

## 阶段诊断

| 阶段 | 进入依据 | 当前首要任务 | 禁止提前做 |
|---|---|---|---|
| 想法 `idea` | 只有能力或方向假设 | 明确客户、场景、问题和证据 | 重资产开发、完整课程、自动化 |
| 验证 `validation` | 有目标客户接触和可测试 offer | 获得真实行为/付费并交付结果 | 产品矩阵、多渠道铺开 |
| 首批成交 `first_sales` | 已出现付费但重复性不足 | 重复验证客户、承诺、价格 | 把偶然订单当稳定收入 |
| 交付 `delivery` | 需求重复出现 | 稳定结果、成本、工时和售后 | 只追获客、不管交付 |
| 系统化 `systemization` | 流程和例外开始稳定 | SOP、模板、质量闸门、外包/AI | 自动化未验证流程 |
| 转全职 `transition` | 业务有持续证据且接近生活目标 | 安全边际、风险和退出预案 | 因一次大单或厌班辞职 |
| 扩张 `expansion` | 核心闭环稳定且容量成为约束 | 提高毛利、复购、转介绍和韧性 | 同时增加多产品、多渠道、团队 |

阶段不是荣誉等级。发现上游证据不足时回退处理。

## 主卡点定位

画出商业闭环：

```text
客户发现 → 问题理解 → offer 理解 → 信任 → 体验/付费
→ 交付 → 结果 → 复购/升级 → 推荐 → 可持续经济性
```

为每一环记录“现象、证据、损失、可干预性”。选择最靠近真实结果、证据最强且当前可验证的一个主卡点。

- 没人询问：先查客户、问题、触达和表达。
- 有询问无付费：查问题优先级、信任、承诺、价格和风险。
- 有付费无结果：先修交付，不加大获客。
- 有结果无利润：查范围、成本、定价、容量和返工。
- 收入增长但时间失控：查标准化、产品形态和客户选择。
- 业务稳定但脆弱：查客户、渠道、产品、平台和创始人单点依赖。

## 证据治理

使用证据账本：

| 陈述 | 类型 | 来源/时间 | 置信度 | 会影响什么决策 | 验证动作 |
|---|---|---|---|---|---|

类型必须为：事实、推断、假设、未知、外部主张。知识库文章中的叙事案例、金额、比例和第三方观点默认是启发式或待核验外部主张，除非用户提供可验证的一手证据。

行为证据通常比态度证据更强：口头认可不能替代预约、定金、付费、完成使用、获得结果、复购或推荐。但也要检查样本偏差、熟人关系、折扣、退款和交付成本。

## 决策输出

先给一句话：

```text
当前处于【阶段】，首要矛盾是【主卡点】；本轮只验证【假设】，暂不做【三项提前动作】。
```

再给最小行动、成功信号、护栏、最大可接受损失、停止/调整条件和复盘日期。没有预先约定停止条件，就不能把坚持或放弃解释为证据。
