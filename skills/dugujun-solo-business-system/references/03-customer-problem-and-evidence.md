# 客户问题与需求证据

## 把想法改写成决策

不要问“这个产品有没有市场”，改问：

```text
哪类人在什么场景出现什么问题？他们现在如何解决？
问题造成什么损失？什么行为能证明它优先到值得付费？
```

## 问题证据卡

为每个问题记录：

- 客户纳入和排除条件。
- 触发场景、频率、持续时间和后果。
- 用户原话与实际行为，分开记录。
- 当前替代方案、切换成本和不满意点。
- 已投入的时间、金钱、组织资源或情绪成本。
- 购买者、使用者和受益者是否为同一人。
- 可能推翻该方向的反证。

不要把“有人提过、有人搜索、有人点赞”直接等同付费需求。它们是不同强度的信号。

## 证据阶梯

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 抱怨/评论/搜索 | 问题存在或有兴趣 | 愿意购买 |
| 愿意接受访谈/留下联系方式 | 愿意投入少量时间 | 问题优先级高 |
| 预约、提交资料、参加测试 | 有具体行动意愿 | 愿意持续付费 |
| 定金/付费 | 承诺和价格有初步吸引力 | 能交付结果或盈利 |
| 完成交付并获得结果 | 方案对该样本有效 | 可复制、可规模化 |
| 复购/升级/转介绍 | 价值与信任更强 | 适合所有客户 |

每条证据同时记录样本来源、是否熟人、是否有折扣、时间窗口和失败样本。

## 访谈与观察

每个问题必须服务一个决策。优先问过去行为而非未来想象：

- 最近一次遇到这个问题是什么时候？
- 当时怎么处理，花了多少时间或钱？
- 为什么现有方案不够？
- 谁决定是否购买，最担心什么？
- 如果不解决，会发生什么？

避免推销式提问、“你会不会买”以及向用户展示答案后再求认同。AI 可协助整理和聚类，用户必须保留深访、矛盾解释和最终判断。

## 问题优先级

比较：发生概率、问题代价、现有投入、决策紧迫性、可触达性、可交付性和战略匹配。不要使用没有依据的统一权重。

结论只允许：

- `go`：有足够行为证据进入付费/交付验证。
- `weak-go`：问题可能存在，但关键证据缺失；先补证。
- `no-go`：反证明显、代价弱、无法触达或不符合约束。

## 数据与当前市场

搜索量、竞品价格、平台分发、政策和行业规模都可能变化。需要当前判断时查实时一手来源；缺少可核数据时输出“如何验证”，不编造市场数字。

进入用户分层、生命周期、会员、复购、LTV、私域或 CRM 深水问题时，路由 `user-operations-playbook`，本模块只保留一人公司产品验证所需的最小用户证据。
